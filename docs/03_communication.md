# 03 溝通

## 規則

### 什麼時候發訊息

1. **只在三種情況發跨 session 訊息**：gate 完成的一份 TASK REPORT、卡住需要決定、要對方立刻改變行動（發工單、裁決、回答問題也算）。
2. **不回 ACK**：不發「收到」「開始了」「做完一半」，做完在檔案和 gate 報告裡交代；對方寫「不用回覆」就不回。
3. **一次完整**：給同一個人的指令、裁決、補充合併成一則；只有會造成錯誤動作的更正才立刻單獨發。長內容放檔案、附路徑。
4. **狀態寫檔**：進度寫在自己的 `RESUME_STATE.md`、排程看板、工單進度；要通知多人就寫進共用檔案一次（規則檔或看板 `NOTICE`）。
5. **等別人做完**：用不叫醒對方的通知（例如 `notify_when_idle`）或背景程序等檔案出現，不發「做完了嗎」。

### PO 的訊息不漏讀

PO 的訊息有三個來源，總監每一個都讀，而且優先於 worker 訊息：
1. **待決頁**（任何喚醒）：每輪第一步（`docs/06`）唯讀收集待決頁和選擇頁的回覆與新留言，接著同輪執行或派工並關閉；未能完成則寫續辦紀錄。
2. **聊天裡的 PO 訊息**（包括工作中途插進來的）：同一輪先處理並登記進 `DECISION_REGISTER.md`；會改變做法的，同一輪寫進規則。
3. **PO 動作項**：PO 說「做好了」，就視同完成，立刻通知相關 worker。
- 每輪結束前自查：待決頁已讀、本輪 PO 訊息已處理並登記、已回覆項目已關閉或留有續辦紀錄。

### PO 待決頁

- 要 PO 回覆、確認或動手的事，一律先放上待決頁（含選擇頁，`docs/12`），一筆一項，格式照 `templates/PO_PENDING.md`；聊天裡只說「待決頁新增了 OD-xx」。
- Worker 要 PO 的任何東西，先報總監（標題 `PO_REPLY_NEEDED`，附問題、選項、建議、影響、圖片路徑），不在自己的對話問 PO。

### 回報給 PO

- 用 PO 指定的語言講白話，非用不可的術語第一次出現就解釋；先結論，只寫結論、要 PO 做的事、還沒驗證的事，細節放檔案。
- Worker 不把同一份內容再傳給 PO。時間戳讀系統時鐘（`date`）。
